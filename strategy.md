2. What are the top 3–5 risks you’d flag to the team before this ships including risks beyond the literal acceptance criteria (UX, edge cases, regression impact)? 
Here are 3 risks can flag to the team:
- Main function must work well
- There is no crash app and no weird layout to make user confusing
- New feature must work well and there is no conflict with the old logic of the system


3. How would you communicate a blocking issue found late in the sprint to developers, PO, and client?
Firstly, QA will reproduce and take note the blocking issue found late in the sprints
Then, QA need to inform the developers, PO, and client to let them aware of the issue
After that, QA follow to resolve it.
